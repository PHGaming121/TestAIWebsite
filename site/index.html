Architecture — and one unavoidable constraint

OpenClaw is a stateful agent server: a long-lived Node process holding a WebSocket Gateway, a SQLite state store, spawned workers, and outbound connections to model providers and chat channels.

✓ What GitHub Pages does well here

  • This documentation site and status record
  • Setup, verification and troubleshooting guides
  • The configuration template and install scripts
  • Deployment via CI on every push to main
  • HTTPS, global CDN, zero cost

✗ What GitHub Pages cannot do

  • Run the Gateway — Pages serves static files only, with no server process, no WebSocket listener and no persistent disk.
  • Keep secrets — everything published to Pages is public.
  • Hold session state or a database.
  • Call model APIs on your behalf (a browser-side key would be exposed to every visitor).

Model routing & failover

OpenClaw resolves models as provider/model. You configure one primary plus an ordered fallback chain; the runtime rotates auth profiles first, then advances down the chain on failover-worthy errors.

PositionModel refRole
Primaryopenrouter/anthropic/claude-sonnet-4-6Strong general reasoning, long context.
Fallback 1openrouter/autoProvider-side auto-routing; absorbs most outages.
Fallback 2openrouter/deepseek/deepseek-v4-proDifferent upstream vendor — independent failure domain.
Fallback 3openrouter/meta-llama/llama-3.3-70b-instructWidely available open-weight last resort.

On “GPT-4” and “Claude 3 Opus”

The original brief asked for those two models. Both are retired — they are no longer the frontier and several are unavailable through current provider endpoints. Hard-coding obsolete IDs would have produced a config that fails on first call. The routing above uses the current generation instead; swap the primary line for openrouter/anthropic/claude-opus-4-6 or an openai/* frontier model if you hold a direct key for one.

Free-tier route

OpenClaw ships a purpose-built command for zero-cost operation — it scans OpenRouter's free catalogue, probes which entries actually support tool-calling and images, and writes the winners into your config: 

openclaw models scan --no-probe --json          # list free candidates (no key needed)
openclaw models scan --set-default --yes        # probe, then promote the best to primary

Free tiers carry rate limits and variable quality; keep a paid fallback in the chain for anything you depend on.

Plugin status — including the requests that don't exist

Three plugins were requested by name. Two of those names do not correspond to any real package, and one is not an OpenClaw plugin at all. Here is the honest mapping, with the real substitutes that were actually installed and configured.

RequestedFindingWhat was done instead
Token Economy Plugin No such package. No OpenClaw plugin by this name exists. Installed @openclaw/tokenjuice — the official, OpenClaw-maintained token-reduction plugin. It compacts noisy exec/bash tool results before they re-enter the context window, which is the single largest token cost in agent loops.
Skill Addition Plugin No such package. Skills are a core subsystem, not a plugin. Configured the built-in skills subsystem (skills.limits, skill entries, on-demand loading) and documented how to add skills. No third-party “skill expansion” module was needed or found.
G0DMOD3 Plugin Exists as a GitHub project, but it is not an OpenClaw plugin — and it is a guardrail-bypass tool. Not integrated. See the note below.

Why G0DMOD3 was not installed

icarnevale/G0DMOD3 (AGPL-3.0) is a standalone multi-model chat front-end. Its own README describes it as built for “red teaming” and “liberated AI,” shipping battle-tested jailbreak prompts and a 33-technique input-perturbation engine whose stated purpose is defeating model safety behaviour. Two independent reasons it stays out:

  • Technically inert here. It is a single-page web app for a static host; it has no OpenClaw plugin manifest, no plugin entry point, and nothing for openclaw plugins install to load.
  • Out of scope by policy. Wiring up tooling whose purpose is to bypass other providers' safety guardrails isn't something this deployment does. It would also breach the terms of service of every upstream API it targets — directly contradicting the compliance requirement in the brief.

If what you actually wanted was a front-end to talk to many models, the Control UI at :18789 plus OpenRouter routing already gives you that, with no bypass tooling attached.

Token reduction in practice

Beyond tokenjuice, the configuration bounds the other major token sinks: the skills index in the system prompt (skills.limits.maxSkillsPromptChars), bootstrap injection (bootstrapMaxChars / bootstrapTotalMaxChars), image downscaling (imageMaxDimensionPx), and the runtime tool-result cap derived from the model's context window.

Reproduce this setup

From a bare machine to a running Gateway. Node 24.16+ or 26.1+ is required.

1 — Install a supported runtime and OpenClaw

# Node 26 (recommended). Any supported install path works.
npm install -g openclaw@latest
openclaw --version        # expect 2026.10.1 or newer

2 — Put your secrets in the environment

cp openclaw/.env.example openclaw/.env      # then edit it
set -a; source openclaw/.env; set +a        # or export the vars your own way

The config never contains a key. It references ${OPENROUTER_API_KEY} and ${OPENCLAW_GATEWAY_TOKEN}, which OpenClaw resolves from the environment at load time — so the file is safe to commit and to publish.

3 — Install the config and the token plugin

mkdir -p ~/.openclaw
cp openclaw/openclaw.json5 ~/.openclaw/openclaw.json
openclaw config validate                              # must print {"valid":true,...}
openclaw plugins install @openclaw/tokenjuice

4 — Start the Gateway

./scripts/start-gateway.sh          # foreground; generates a token on first run
openclaw gateway status             # from another shell
openclaw dashboard                  # opens the Control UI

5 — Prove it works

./scripts/verify.sh                 # full checklist → reports/verification-report.md

Keep the Gateway running without a terminal

openclaw gateway install            # systemd user unit / launchd / Scheduled Task
openclaw gateway status

Troubleshooting

Gateway refuses to start after I edited the config

OpenClaw validates strictly: one unknown key or wrong type stops the boot. Only diagnostic commands work in that state. 

openclaw doctor              # show the exact schema violations
openclaw doctor --fix        # repair legacy keys, restores last-known-good if needed
openclaw config validate     # confirm before restarting

OpenClaw also guards against accidental clobbering — a write that drops gateway.mode or shrinks the file by more than half is blocked and saved as openclaw.json.clobbered.<timestamp> instead of applied.

“Unsupported Node version”

The package installs, then the CLI refuses to run. Install a supported runtime:

nvm install 26 && nvm use 26 && nvm alias default 26
openclaw --version
Control UI loads but the browser will not connect

The WebSocket origin check rejected your page. Add the full origin (scheme + host, no trailing path) to gateway.controlUi.allowedOrigins — and never publish ["*"] to a public host. 

openclaw config set gateway.controlUi.allowedOrigins \
  '["https://your-dashboard.example.com"]'
openclaw config validate && openclaw gateway restart
Port 18789 already in use 
openclaw gateway run --force      # reclaim the port
# or move the Gateway, and update anything that points at it:
openclaw config set gateway.port 19001
Every model route reports “indeterminate”

No usable credential was found. Authenticate, then re-check:

openclaw models auth login --provider openrouter
openclaw models status
Plugin installed but does nothing 
openclaw plugins list                 # confirm the enabled state
openclaw plugins inspect tokenjuice --runtime --json
openclaw plugins doctor               # load errors
openclaw plugins enable tokenjuice
Gateway is slow to start

Doctor's own suggestion for small hosts — cold starts dominated by module compilation:

export NODE_COMPILE_CACHE=/var/tmp/openclaw-compile-cache
mkdir -p /var/tmp/openclaw-compile-cache

Security posture

What this setup enforces

  • No secrets in the repo. Keys resolve from environment variables via ${VAR} substitution.
  • Token auth on the Gateway (gateway.auth.mode: "token"); the token is generated on first run into a 0600 file.
  • Auth rate limiting — 10 attempts / 60 s, then a 5-minute lockout, with loopback exempt.
  • Origin allowlist for Control UI / WebChat WebSockets.
  • Telemetry off; audit logging on.
  • No jailbreak tooling — keeps every upstream API call inside its terms of service.

What you must still do

  • Set a spending limit in your provider account. OpenClaw has no dollar-value budget key; the cap belongs upstream of it.
  • Keep gateway.bind: "loopback" unless you genuinely need all-interface exposure. The shipped template documents the trade-off.
  • Rotate the gateway token if it is ever displayed or shared.
  • Review before exposing: bind + auth + origin allowlist are one policy, and weakening any one of them changes the security of the other two.
