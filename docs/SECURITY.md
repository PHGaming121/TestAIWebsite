# Security guide

How credentials are handled in this setup, what is enforced by configuration, and what
remains your responsibility.

---

## 1. Secrets never live in the config

`openclaw/openclaw.json5` contains **no credential values**. It contains references:

```json5
gateway: { auth: { token: "${OPENCLAW_GATEWAY_TOKEN}" } }
```

OpenClaw substitutes environment variables when it loads the config. Consequences:

- The config file is safe to commit, review, and publish — and it is published, at
  `site/`-adjacent paths in this repository.
- A leaked config leaks no credential.
- Rotating a key means changing an environment variable, not editing and redeploying config.

**A missing variable does not silently degrade.** OpenClaw leaves the `${VAR}` literal in
place and logs a warning, so the failure mode is a visible "unresolved config value", not a
Gateway running with an empty password.

### Where the secrets actually go

| Secret | Where it lives | Notes |
| --- | --- | --- |
| Provider API keys | Environment of the Gateway process, or the local auth-profile store (`~/.openclaw/agents/<agent>/agent/*.sqlite`) | Never in git |
| Gateway token | `$OPENCLAW_STATE_DIR/.env`, mode `600`, generated by `scripts/start-gateway.sh` | Never in git |
| Channel tokens (Telegram, Discord, …) | Environment or the auth store | Per-channel docs apply |

`openclaw/.env.example` contains **placeholders only**, of the deliberately-obvious kind
recommended by OpenClaw's own secret-placeholder conventions
(`example-openrouter-key-not-real`). No realistic-looking key prefixes appear anywhere in
the repository, so secret scanners stay quiet and nobody copies a real-looking fake key.

### Guardrails in this repository

- `.gitignore` excludes `openclaw/.env`, `*.env` (except the example), and the state
  directory's local copies.
- The Pages workflow **fails the build** if it detects anything matching a credential
  pattern (`sk-or-v1-…`, `sk-…`, `ghp_…`) in the published artifact.

## 2. Authentication at the Gateway

Shipped configuration:

```json5
gateway: {
  auth: {
    mode: "token",
    token: "${OPENCLAW_GATEWAY_TOKEN}",
    rateLimit: { maxAttempts: 10, windowMs: 60000, lockoutMs: 300000, exemptLoopback: true },
  },
}
```

- **`mode: "token"`** — every client must present the shared token to connect. Options are
  `none`, `token`, `password`, and `trusted-proxy`. `none` means anyone who can reach the
  port controls your assistant; it is appropriate only on a loopback-only host.
- **Rate limiting** — 10 failed attempts per 60 seconds triggers a 5-minute lockout. This is
  brute-force throttling at the gateway boundary; it does not replace a long random token.
- **`exemptLoopback: true`** — local development is not throttled. Remote clients are.
- **`trusted-proxy`** is only for a reverse proxy that genuinely performs authentication
  itself and strips client-supplied identity headers. Configured incorrectly, it lets anyone
  claim any identity.

`./scripts/verify.sh` check 8 fails the run if `auth.mode` is `none`.

### Network exposure

| Setting | Meaning |
| --- | --- |
| `bind: "loopback"` | Local only. **The safe default on a normal host.** |
| `bind: "lan"` | Reachable on your local network |
| `bind: "tailnet"` | Reachable on your Tailscale network |
| `bind: "custom"` + `customBindHost: "0.0.0.0"` | Every interface — needed behind a container/port proxy, and the widest exposure |

The template ships `0.0.0.0` because the reference deployment sits behind a port proxy. On
your own machine, change it:

```bash
openclaw config set gateway.bind loopback
```

The Gateway logs a warning when it binds to a non-loopback address. Treat that warning as a
prompt to confirm auth is configured.

## 3. Browser origins

Control UI and WebChat are WebSocket clients, so the Gateway enforces an origin allowlist:

```json5
gateway: { controlUi: { allowedOrigins: ["https://your-dashboard.example.com"] } }
```

- Full origins only (scheme + host, no path). Exact matches — subdomains are separate.
- `["*"]` allows any origin. OpenClaw's own schema documentation says this "should be
  avoided outside tightly controlled local testing". Do not ship it publicly: any website a
  logged-in user visits could then open a socket to their Gateway.
- `gateway.controlUi.dangerouslyAllowHostHeaderOriginFallback` exists and is named
  `dangerously` for a reason. An explicit allowlist is the hardened default.

## 4. What this setup does not do

**It does not implement a dollar-value spending cap, because OpenClaw has no such config
key.** The schema is strict; inventing `spendingLimit: 50` would fail validation. Cost
control therefore lives in three places:

| Layer | Mechanism | Enforced by |
| --- | --- | --- |
| Hard cap | Provider-side spend limits and prepaid credits | OpenRouter / Anthropic / OpenAI account settings |
| Visibility | `/status`, `/usage cost`, Control UI → Usage, `openclaw status --usage` (`X% left`) | OpenClaw |
| Blast radius | `modelPolicy.allow`, token-reduction plugin, context limits | This configuration |

Set the hard cap in your provider account. It is the only layer that cannot be bypassed by
a runaway agent loop.

**It does not install jailbreak or guardrail-bypass tooling.** See
[PLUGINS.md](PLUGINS.md#3-g0dmod3-plugin--not-installed-deliberately). Beyond the technical
mismatch, such tooling breaches the terms of service of the APIs it targets — which is
incompatible with running a compliant deployment.

**It does not authorise anyone to use your assistant.** Installing the Gateway does not
grant access. Channel access is governed by pairing and allowlists, and you should configure
those deliberately before connecting a bot to a group chat.

## 5. Compliance notes

- **Provider terms of service.** Use each provider's API within its published limits and
  policies. Credential reuse through unofficial paths is a common cause of account
  suspension. Note that Anthropic has publicly sanctioned Claude CLI reuse as an integration
  pattern (as of 2026-07-05) unless policy changes — recheck current terms before relying on
  it.
- **Data handling.** Sessions, transcripts and memory live in the local SQLite store in the
  state directory. That is your data, on your disk — back it up
  (`openclaw backup create`) and delete it deliberately (`openclaw backup` /
  session management commands) rather than assuming it disappears.
- **Telemetry.** `telemetry.enabled: false` in the shipped config. OpenClaw's default is a
  version check, which you can leave off.
- **Audit.** `logging.audit.enabled: true` records activity records you can inspect with
  `openclaw audit`.

## 6. Hardening checklist

- [ ] Gateway token is long and random (the start script generates 32 bytes).
- [ ] `gateway.bind` is `loopback` unless the host genuinely needs otherwise.
- [ ] `gateway.auth.mode` is `token` or `password` — never `none` on a reachable interface.
- [ ] Rate limiting enabled (shipped default: 10 per 60 s → 5 min lockout).
- [ ] `controlUi.allowedOrigins` lists your real origins and nothing else.
- [ ] `publicOrigin` set if you are behind TLS, so generated links are correct.
- [ ] Provider-side spend limits configured.
- [ ] Secrets in the environment or the `0600` state file — never in git, never on Pages.
- [ ] `openclaw/.env` is git-ignored (verified by `.gitignore`).
- [ ] Third-party plugins reviewed before install; official inventory preferred.
- [ ] Channel allowlists/pairing configured before connecting any bot.
- [ ] `./scripts/verify.sh` passes, including the auth check.

---

## 7. If something goes wrong

| Event | Action |
| --- | --- |
| Key committed to git | Rotate it **first**, then clean history. Assume it is compromised the moment it is pushed. |
| Gateway token exposed | Regenerate the token, restart the Gateway, update clients. |
| Suspicious model spend | Check provider usage dashboards; `openclaw status --usage` for quota windows; `openclaw audit` for activity records. |
| Unknown plugin installed | `openclaw plugins inspect <id> --runtime --json`, then `openclaw plugins uninstall <id>`. |
| Suspected compromise | `openclaw gateway stop`, rotate every credential, review `openclaw audit`, then rebuild state from a known-good backup. |
